# 变温系统首轮验证

## 目的

使用真实模块 `变温系统` 对 `openclaw-fmea-cocreator` 做首轮验证，检查它是否能从已有项目资料中完成下面这条链路：

1. 从自然语言描述识别分析范围
2. 召回相似历史失效案例
3. 生成结构化 DFMEA 草稿
4. 标出必须人工确认的评分和边界
5. 反推 skill 还需要补什么

## 验证对象

- 模块名称：`变温系统`
- FMEA 类型：`DFMEA`
- 首轮验证选择理由：当前项目中该模块资料最完整，同时兼具自然语言输入样例与成品 DFMEA 样例

## 输入来源

### 原始输入样板

主要来自：

- `excel_materials/workbooks/CAN400产品DFMEA/json/01_项目计划.json`
- Excel 行号：`13`

这段输入本身已经很接近真实共创场景，内容包括：

- 压缩机制冷单元
- 气液分离器、蒸发器、压缩机、冷媒 R454C
- 控制板卡、422 通讯、继电器、传感器、高压保护、24V 供电、220V 强电
- 液氮低温制冷系统
- 液氮罐、排气管组件、主体组件、紫铜盘管、特氟龙连接、三通阀、加热棒、PT100、航插、真空腔、波纹管、麦拉膜和 G10 隔热环

### 输入识别后的关键判断

首轮验证的一个重要结论是：

`变温系统` 并不是一个单一物理架构，而是混合了两套子系统：

1. 压缩机制冷子系统
2. 液氮蒸发/换热子系统

因此正式共创时，不应直接把全部内容混成一张“无边界”的表，而应先拆 scope。

本次验证按两个子系统分别起草，但仍保留在同一份验证文档中。

## 当前草稿里的 Top 风险

按首版草稿排序，建议优先盯这几类：

1. `RPN 336`：0档停机逻辑未执行抽空，导致液击
2. `RPN 336`：紫铜管与 PTFE 连接处冷缩泄漏
3. `RPN 294`：振动过大导致谱图边带和信噪比下降
4. `RPN 280`：启动时序不当导致带液启动
5. `RPN 240`：冰堵或脏堵
6. `RPN 224`：换热盘管冰堵（当前 `O/D` 仍属低置信度草稿）

## 必须人工确认的项

### 1. 分析范围是否要正式拆表

当前最应该确认的是：

- 正式版是否拆成 `压缩机制冷子系统 DFMEA`
- 与 `液氮蒸发子系统 DFMEA`

如果不拆，后续责任归属、控制措施和案例沉淀都会混乱。

### 2. O / D 的企业化校准

尤其需要专家确认：

- 冰堵/脏堵
- 振动过大
- 通讯心跳丢失
- PTFE 冷缩泄漏
- 换热盘管冰堵

这些项的 `O` 与 `D` 高度依赖：

- 焊接清洁度
- 低温验证能力
- EMC 水平
- 现场检测与试验手段

### 3. 当前控制是否真实存在

草稿里多处建议默认依赖了“历史案例里出现过的控制”：

- 氦质谱检漏
- 机械式高压开关
- 通讯心跳保护
- 低液位联锁
- 振动/模态验证

这些在正式输出前需要逐项确认是否已经落地。

## 这次验证对 skill 的直接结论

### 已证明有效的部分

- 能从项目里的自然语言描述识别出这是一个 `DFMEA` 共创任务
- 能从本地案例库里召回高度相关的历史条目
- 能形成结构化的首版草稿，而不是只吐一段自由文本
- 能明确指出哪些项更适合 AI 草拟，哪些必须人工确认

### 这次验证暴露出来的改进点

1. skill 需要先做 `scope split`
   - 一个模块描述里可能混了多个物理架构，不能直接一锅端

2. 案例检索默认应优先样例库
   - 计划说明类文本容易干扰检索结果
   - 本轮已把检索脚本默认收敛到 `dfmea_sample_data` 和案例模板

3. 还缺“从检索结果自动拼装首版表格”的辅助脚本
   - 当前草稿仍由人工整合
   - 下一步可考虑加一个 `draft_fmea_from_cases.py`

4. 还缺企业评分标尺
   - 没有 `S/O/D` 的企业内定义表时，skill 只能给草稿分

5. 还缺 OpenClaw 交互映射
   - 目前 skill 已具备流程和参考资料，但还没有具体的 OpenClaw 表单/节点映射

### 本轮新增进展

基于这次验证，已经新增脚本：

- `openclaw-fmea-cocreator/scripts/draft_fmea_from_cases.py`

它现在支持两种方式：

1. 不传 `--scope`
   - 自动根据模块名和输入文本建议 scope

2. 显式传入 `--scope`
   - 用人工定义的子系统范围覆盖自动建议

对应的自动 scope 产物已输出到：

- `validation/generated/变温系统_auto_scope_draft.xlsx`
- `validation/generated/变温系统_auto_scope_draft.md`
- `validation/generated/变温系统_auto_scope_draft.json`

## 建议的下一步

基于这次验证，最合理的下一步是：

1. 增加一个“从自然语言输入生成结构化首版表格”的脚本

3. 把 `变温系统` 正式拆成两张子系统 DFMEA 试跑一次
