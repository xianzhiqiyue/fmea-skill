# Input Checklist

Use this checklist to gather enough material for a useful FMEA draft.

## Minimum viable input

Try to get at least:

- project or product name
- module or analysis object name
- FMEA type: `AFMEA`, `SFMEA`, or `DFMEA`
- key function or requirement
- use scenario or lifecycle stage

## Strongly recommended input

- functional description
- scope boundary: one table or multiple child scopes
- subsystem or component boundaries
- interfaces: structure, signal, energy, fluid, motion
- operating environment
- design constraints
- customer impact or downstream-process impact

## High-value source material

These are especially valuable when available:

- BOM or key part list
- design spec or requirements
- task or operation flow
- transport, storage, use, maintenance conditions
- historical complaints, repairs, or old FMEA rows
- current controls, tests, inspections, alarms, interlocks

## Best checklist by task type

### AFMEA

- lifecycle stage
- storage or transport condition
- operation steps
- maintenance process
- environment stress

### SFMEA

- system breakdown
- subsystem functions
- interface relationships
- energy or signal paths

### DFMEA

- module decomposition to part level
- BOM
- design requirements and critical characteristics
- materials, tolerances, connection methods

## Missing input behavior

If important inputs are missing:

- make a reasonable assumption
- label it explicitly
- continue drafting
- end with a short list of the most valuable missing data
